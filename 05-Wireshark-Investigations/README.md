# Wireshark Network Investigations

## Overview

Analyze controlled HTTP, DNS, HTTPS, and periodic HTTP traffic
to understand network behavior and the limits of packet evidence.

## Lab Environment

- VMware Fusion on a MacBook Air.
- Network: Private to my Mac.
- Windows client: 172.16.152.129.
- Kali server and capture system: 172.16.152.128.
- Tools: Wireshark, Python, dnsmasq, OpenSSL, and PowerShell.

## Investigations Completed

| Exercise | Focus |
|---|---|
| HTTP over TCP | Handshake, requests, responses, and readable content |
| DNS over UDP | Query-response matching and address resolution |
| HTTPS over TLS | Encrypted traffic and visible connection metadata |
| Periodic HTTP | Repeated requests, timing, and alternative explanations |

## Key Findings

- HTTP exposed readable requests, response headers, and page content.
- A 404 response for the favicon did not mean the server was unavailable.
- The DNS server returned 172.16.152.128 for soc-lab.test.
- HTTPS exposed connection metadata while HTTP content remained
  unreadable without TLS decryption.
- Six requests for /heartbeat.txt occurred approximately
  5.13–5.39 seconds apart, with six HTTP 200 responses.
- Regular communication supported identifying automation but did
  not establish malware.

- Identifying clients, servers, ports, and TCP handshakes.
- Reading HTTP requests and responses.
