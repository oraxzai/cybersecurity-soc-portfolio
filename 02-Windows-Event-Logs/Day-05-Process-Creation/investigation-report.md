# Investigation Report: Windows Process Creation

## Summary

On September 9, 2026, I examined two Windows Security 4688 events
generated by a controlled command in my Windows VM:

    cmd.exe /c whoami

The records show a cmd.exe process starting whoami.exe under the
Healisu account. The evidence matches the authorized exercise.

## Investigation Scope

- Host: DESKTOP-C70T8EA
- Log: Windows Security
- Event ID: 4688 — Process Creation
- Event Record IDs: 4971 and 4972
- Tools: Event Viewer and Command Prompt

Process Creation auditing and command-line recording were enabled
before generating the events.

## Timeline

Date: September 9, 2026.
Times are rounded to milliseconds.

| Record ID | Local time (UTC+05:00) | UTC time | New process |
|---|---|---|---|
| 4971 | 12:51:27.970 | 07:51:27.970 | cmd.exe |
| 4972 | 12:51:27.997 | 07:51:27.997 | whoami.exe |

The process starts occurred approximately 27 milliseconds apart,
calculated from the full XML timestamps.

## Evidence Analysis

### Record 4971 — Command Prompt Created

- New Process Name: C:\Windows\System32\cmd.exe
- New Process ID: 0x18a4
- Creator Process Name: C:\Windows\System32\cmd.exe
- Creator Process ID: 0xf58
- Command Line: cmd.exe /c whoami
- Creator Account: Healisu
- Creator Logon ID: 0x44A11

This record shows the original Command Prompt starting a second
instance of cmd.exe with instructions to execute whoami.

### Record 4972 — whoami Created

- New Process Name: C:\Windows\System32\whoami.exe
- New Process ID: 0x1a94
- Creator Process Name: C:\Windows\System32\cmd.exe
- Creator Process ID: 0x18a4
- Command Line: whoami
- Creator Account: Healisu
- Creator Logon ID: 0x44A11

The Creator Process ID matches the New Process ID in record 4971.

## Parent-Child Correlation

| Process | PID | Parent PID |
|---|---|---|
| Original cmd.exe | 0xf58 | Not established by the reviewed records |
| New cmd.exe | 0x18a4 | 0xf58 |
| whoami.exe | 0x1a94 | 0x18a4 |

The PID relationship is supported by the matching host, account,
session, executable paths, command lines, and close timestamps.

The same Logon ID indicates the shared session context in these
records. Different PIDs distinguish the separate process instances.

The XML System/Execution ProcessID value of 4 was not used as the
parent PID. It describes event-provider execution information.

## Privilege Context

Both events recorded:
- Token Elevation Type: %%1937
- Mandatory Label: High Mandatory Level

These values indicate elevated processes and match the use of
an Administrator Command Prompt.

Elevation is relevant context but does not independently establish
malicious activity.

## Assessment

Classification: Authorized lab activity.

The reviewed process events match the deliberately executed command.
No malicious activity was established from the reviewed evidence.

In a company environment, the presence of whoami.exe would require
context: it can be used for legitimate administration or by an
attacker checking the account under which code is running.

## Investigation Limitations

- Only two process-creation records were analyzed.
- The original shell's own creation event was not reviewed.
- Event 4688 does not capture command output or prove successful
  completion.
- Process termination, file activity, and network activity were
  not reviewed.
- PIDs can be reused; correlation requires host and time context.
- No SIEM detection rule or alert was generated.

## Actions Taken

1. Enabled and verified process-creation auditing.
2. Enabled and verified command-line inclusion.
3. Executed the controlled command.
4. Located and examined the two corresponding 4688 records.
5. Correlated the parent and child processes.
6. Documented findings and supporting screenshots.

No containment action was needed for the known authorized exercise.
